# Regime-Shift Tactical Asset Allocation Engine

A market-regime detection and tactical asset allocation system for Indian markets. A Gaussian Hidden Markov Model infers, without any hand-labeling, which of three latent regimes — **Bull / Bear / Crisis** — the market is in each day, and a convex optimizer (cvxpy) re-solves portfolio weights across equities, gold and bonds with a **different objective per regime**. Everything is evaluated with a leak-free expanding walk-forward harness and transaction costs.

Built as the Summer of Quant (SoQ) advanced project.

## Results

Real-data results are generated by `python run_pipeline.py` and written to [`results/RESULTS.md`](results/RESULTS.md) (metrics table + regime chart + equity curves + drawdown). The committed results were produced by that exact command; rerun it to reproduce.

## How it works

```
prices (NIFTY, gold ETF, gilt ETF) + India VIX          [src/data.py]
        │  inner-join on trading dates, NaN audit
        ▼
features: 1d log-return, 63d momentum, 21d realized vol,
          VIX vs its 1y average — all backward-looking    [src/features.py]
        ▼
expanding walk-forward loop                               [src/walkforward.py]
  per fold: scaler fit on TRAIN only → GaussianHMM fit on TRAIN only
            (5 seeds, best log-likelihood) → states relabeled to
            Bull/Bear/Crisis by ascending vol mean →
            TEST days labeled causally (Viterbi on data ≤ t only)
        ▼
per-regime μ_k, Σ_k from TRAIN days → cvxpy weights       [src/portfolio.py]
  Bull:   max  μᵀw − 2·wᵀΣw          (return-seeking)
  Bear:   max  μᵀw − 10·wᵀΣw         (balanced)
  Crisis: min  wᵀΣw                   (pure min-variance)
  long-only, fully invested, 70% per-asset cap
        ▼
backtest: weights.shift(1), 10 bps cost on turnover,
          2-day regime confirmation debounce; benchmarks: 60/40, equal-weight
```

## Design decisions (and why)

**Why 3 regimes?** Bull/Bear/Crisis is the smallest state space that separates "calm decline" from "panic" — the two need different portfolios (a Bear tilt vs. a flight to min-variance). K is a modeling choice, not learned; the state count is deliberately kept small because each extra state adds a full (μ, Σ) block to estimate from limited daily data.

**Why `covariance_type="diag"`?** Full covariance triples the per-state parameter count for 4 features; with a few thousand training days per fold, diagonal covariances fit more stably and the multi-seed selection compensates for the rougher geometry.

**Anonymous states → labels.** HMM state indices mean nothing (state "0" is arbitrary per fit). States are mapped to Bull/Bear/Crisis by sorting on the mean of the volatility feature. Because the mapping is recomputed every fold, this also solves the **cross-fold relabeling problem** — state indices are never compared across fits, only canonical labels are.

**Causal labeling.** `model.predict(window)` is smoothed — it uses data from *later* in the window to label earlier days. Test-day labels here are produced by running Viterbi on data up to day *t* only, one day at a time, so the label for *t* never sees *t+1*.

**Multi-seed EM.** Baum–Welch converges to a local optimum; each fold fits from 5 seeds and keeps the best log-likelihood.

**Costs and debounce.** 10 bps one-way on turnover. Raw daily regime labels whipsaw; a switch is adopted only after 2 consecutive days of the new label, which cuts single-day flip costs. Both gross and net results are reported so the cost drag is visible rather than hidden.

**Leak-safety is tested, not assumed.** `tests/test_pipeline.py` includes a perturbation test: modify all prices *after* date t and assert every feature row *before* t is bit-identical. Scaling stats and per-regime (μ, Σ) come from the training window only, per fold, by construction.

## Repo layout

```
src/data.py         yfinance pulls, validation, alignment
src/features.py     backward-looking features (VOL_COL drives state labeling)
src/hmm_model.py    multi-seed fit, canonical relabeling, causal prediction
src/walkforward.py  expanding folds, train-only scaling/fitting, fold stats
src/portfolio.py    cvxpy per-regime weights, debounce, backtest, metrics
src/synthetic.py    3-regime simulator (offline validation + tests)
run_pipeline.py     end-to-end runner → results/
tests/              leak guards, optimizer sanity, e2e + regime recovery
notebooks/          thin notebook that drives the same modules
```

## Limitations & honest caveats

- Weight drift between rebalances is ignored (targets held constant) — applied consistently to strategy and benchmarks, but it is a simplification.
- Regime-conditional (μ_k, Σ_k) are sample estimates from training days; Bull/Bear means in particular are noisy, which is why risk-aversion differs by regime rather than chasing point estimates of μ.
- Indian ETF histories on Yahoo Finance are shorter and patchier than US equivalents; `src/data.py` validates coverage and fails loudly with instructions rather than silently truncating.
- Turnover is still meaningful even after the debounce; a transaction-cost-aware rebalancing band is the natural next extension.
- With ~2 decades of daily data at most, the number of genuinely independent Crisis episodes is small; out-of-sample regime statistics should be read with that in mind.
